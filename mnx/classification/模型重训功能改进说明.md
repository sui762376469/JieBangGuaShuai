### **3. 自动清理旧文件** ✅

#### **功能描述**
在开始训练新模型之前，系统会自动删除旧的模型文件和映射文件，确保使用全新的配置。

#### **清理的文件**
- ❌ `category_map.json` - 旧的类别映射文件
- ❌ `mlp_model.pth` - 旧的模型权重文件
- ❌ `mlp_encoder.pkl` - 旧的标签编码器

#### **执行流程**
```
用户点击"开始训练"
  ↓
显示清理提示
  ↓
🧹 清理旧文件
  ├─ 删除 category_map.json
  ├─ 删除 mlp_model.pth
  └─ 删除 mlp_encoder.pkl
  ↓
📖 读取新的标签映射表
  ↓
💾 生成新的 category_map.json
  ↓
🎯 训练新模型
  ↓
💾 保存新的 mlp_model.pth 和 mlp_encoder.pkl
  ↓
✅ 训练完成
```

#### **控制台输出示例**
```
🧹 正在清理旧的模型文件...
  🗑️  已删除: category_map.json
  🗑️  已删除: mlp_model.pth
  🗑️  已删除: mlp_encoder.pkl
✅ 已清理 3 个旧文件: category_map.json, mlp_model.pth, mlp_encoder.pkl
```

#### **UI 提示**
点击"开始训练"按钮后，会显示：
```

3. 使用新的标签映射表重新训练模型

```

## 🎯 解决的问题

### **问题1：category_map.json 不完整导致预测失败**

**症状**：
```
[API 映射] 加载了 10 个类别映射
⚠️ API 返回的类别编号 0 不在 category_map.json 中
台账显示：预测类别 = None
```

**原因**：
- 用户上传的标签映射表本身就不完整
- 没有验证机制，不完整的映射表被直接保存

**解决方案**：
1. ✅ 上传后立即显示所有识别到的类别
2. ✅ 自动检测缺失的类别并警告
3. ✅ 如果有缺失，禁用"开始训练"按钮
4. ✅ 提供标准模板确保完整性

---

### **问题2：旧模型文件干扰新训练**

**症状**：
- 使用旧的 `category_map.json` 导致类别不一致
- 模型缓存未清空，仍使用旧的模型参数
- 预测结果混乱

**原因**：
- 训练前没有清理旧文件
- 模型缓存 `_MODEL_CACHE` 未清空

**解决方案**：
1. ✅ 训练前自动删除所有旧文件
2. ✅ 清空模型缓存
3. ✅ 显示清理过程让用户知晓
4. ✅ 确保使用全新的配置

1. 下载标准模板
2. 直接使用或修改中文名称
3. 上传训练数据集和标签映射表
4. 检查预览区域确认完整性
5. 点击"开始训练"

#### **场景2：重新训练（修改类别）**
1. 准备新的标签映射表（确保完整）
2. 上传新文件
3. 系统会自动清理旧文件
4. 检查预览确认新类别
5. 点击"开始训练"

#### **场景3：仅更新数据（类别不变）**
1. 使用相同的标签映射表
2. 上传新的训练数据集
3. 系统会清理旧模型但保留类别定义
4. 点击"开始训练"

### **注意事项**

⚠️ **重要提醒**：

1. **每次训练都会删除旧文件**
   - 这是正常行为，确保配置一致性
   - 如果需要备份，请手动复制旧文件

2. **标签映射表必须完整**
   - 必须包含所有17个类别（0-16）
   - 缺失类别会导致训练失败
   - 使用标准模板最安全

3. **训练完成后立即生效**
   - 新模型会自动部署
   - 无需重启应用
   - 可以立即进行预测

4. **类别名称可以修改**
   - 可以修改中文名称以适应业务需求
   - 但不要修改标签序号（0-16）
   - 修改后记得更新相关文档
